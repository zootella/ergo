# ergo

Ergo, short for ergonomic, is a small dependency-free library of helper functions shipped in four languages: JavaScript, Python, Rust, and Go. Two things are true at once. The four editions are one library, with the same function names and the same behavior, proven by a single shared test suite that all four run. And each edition is a native of its own ecosystem, written, formatted, packaged, and tested the way that language does it, so an experienced engineer in that language finds nothing foreign. concept.md explains how the two fit together; read it for the full idea and where it came from, construction.md for how each of the four editions is defined, tested, and shipped, ideas.md for ideas beyond the core requirements, including the brand, ruby.md for whether to add a fifth language, and tag.md for what a tag is worth against a UUID and the objections already answered.

## Rules

- style.md is the style guide for how code is structured, named, commented, and factored: simplicity, dense comments, result objects over exceptions, guards at trust boundaries, fewer longer files. It's written for JavaScript, but its values hold in every edition.
- Style is not format. style.md's Layout section does not apply in this repository. Formatting is each language's standard formatter, Prettier, Ruff, rustfmt, and gofmt, run on save and checked in CI; see construction.md. Names keep the same words in every edition and take each language's case, so `Size.KB` in Python and `size::KB` in Rust are right, while JavaScript stays lowercase camelCase even for constants, `Size.kb`, by choice, to avoid shouts; construction.md has the table of spellings and concept.md the note. Where a language's formatter or its case convention disagrees with style.md, the language wins. Everywhere else, style.md wins. The test: a mid-career engineer in each language looks at their edition, runs their regular linter, and things are fine.
- `ttd` notes belong to the user alone. Never add, reword, or remove one. See style.md.
- Zero runtime dependencies, in every language. Use the platform.
- No toss and no TossError. When an edition can't continue, it fails the way its language fails: throw an Error in JavaScript, raise in Python, panic in Rust and Go. Exceptions are the last and hardest thing ergo will make easy, not the first.
- Integers have one ceiling in every edition and every vector, JavaScript's safe range of ±(2^53 − 1), so a value within it survives all four runtimes as an integer.
- The unit suite is deterministic and fast: pinned data, nothing random, tens of milliseconds. Fuzz tests draw random inputs for a set number of seconds and run only when `ERGO_FUZZ` names the seconds: the cross-edition one, about uniformity, with `ERGO_FUZZ=4 pnpm fuzz`, and the same loop in each language, about performance; README.md has the four commands.
- One test suite, four harnesses. The tests are the specification. A function's behavior is pinned once, in the shared suite, and each language's harness confirms its own implementation against it.
- The user introduces ideas one part at a time. While they're presenting, listen and acknowledge. Don't lay out the path forward until asked.

## Status

- Four families in all four editions: the Size constants and `saySize4`, the Time constants, the tick, an integer of milliseconds since 1970 with two exact text forms, `tickToText` and `tickToIso` and their readers back, and the Tag family, `Tag`, `hasTag`, `checkTag`, and `tagLength`, where a scripted test proves a tag from any edition validates in every edition. The shared vectors are one json file per family in tests/, a driver per edition, the vitest suite in javascript/ drives all four and holds the fuzz test, formatters and linters pass in each, the two workflows, and the VitePress site in docs/ has a page per family. README.md says how to run everything; the vitest suite needs all four toolchains installed.
- Not yet under git. It will become github.com/zootella/ergo. The user creates the repo and clones it here.
- Source material is ../cold3/icarus/core.js, which imports its test harness and guards from ../cold3/icarus/level0.js. icarus is a mine, not a museum: ergo takes the gems from both, function by function, and leaves the rough and early parts behind, including toss and TossError.
- The protocol's canonical function names are the JavaScript edition's; each edition spells them its own way, like `saySize4`, `say_size4`, `say_size4`, `SaySize4`, and `Size.kb`, `Size.KB`, `size::KB`, `ergo.KB`. A constant is a function with no arguments, and a dotted name reaches into a namespace of them. Adding a function means a vector file, four implementations, and a line in each of the four dispatch tables.
